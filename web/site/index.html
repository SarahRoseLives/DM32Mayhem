DM32Mayhem

Mayhem, for a handheld. DM32Mayhem is free, open-source firmware for the Baofeng DM-32UV, inspired by the HackRF PortaPack Mayhem project: the same spirit of doing things with a radio you wouldn't expect, then adding more cool features as we go.

It is an FM transceiver with live PTT, a set of transmit tools — APRS, P25 control channel, MDC-1200, SAME, OOK and RTTY — and receivers for RTTY and APRS. Flash it from your browser, keep your backup, and join the experiment.

In the spirit of Mayhem

HackRF's PortaPack Mayhem showed what a radio becomes when you treat it as a playground: spectrum tools, transmitters and odd little experiments, all in one place. DM32Mayhem brings that attitude to a cheap Baofeng handheld — do things with the radio you wouldn't expect, and keep adding the features that seem fun.

It is not a port and shares no code with PortaPack Mayhem. It is the same idea, written for this hardware under the MIT licence, one experiment at a time.

What it does

Most of this started as “wouldn't it be cool if the radio could…”. The apps share one tile grid and each one keys, tunes and unkeys the radio itself, so a single handheld can send a weather header, a P25 control channel, a page or an APRS beacon.

An FM transceiver, not just a receiver

Set the TX and RX frequencies directly, pick a repeater offset, and give RX and TX their own CTCSS. Hold PTT to talk; release to listen. It is the one screen where PTT keys the radio. How to use it →

Six transmit apps

SAME weather headers, OOK and de Bruijn remote codes, TV test patterns, MDC-1200 ANI/PTT ID, a P25 Phase 1 control channel, APRS status/messages/position, and ITA2 RTTY. Each queues a job and the radio keys, tunes and unkeys itself. See every app →

A real RTTY receiver

Two-tone FSK from the FM discriminator audio, a bit clock that locks to the tone changes, and ITA2 decoding at 45.45 or 50 baud. Mark, shift and invert are settings; the text scrolls in a log and opens full screen.

APRS and DMR

The APRS engine for beacons, messages and positions, with KISS and iGate paths in network builds. DMR receive uses the radio's own AMBE codec, merged by the flasher from the radio.

A boot gate and a tile grid

Every power-on opens with a responsibility notice and a six-digit code generated for that boot. Nothing runs until it is typed. Past it, the apps sit in a grid grouped by direction: RX, TX and TRX.

Flash from the browser

The web flasher backs up the original firmware, installs DM32Mayhem, restores a backup and updates an installed radio, over the programming cable in Chrome or Edge. Your backups stay on your computer.

Honest limits

  • DMR voice needs the codec. Install with the flasher and it keeps the radio's own AMBE codec; a build without one has no DMR voice.
  • POCSAG is not ready. The protocol code is in the tree, but the receiver does not decode reliably yet, so its apps are hidden.
  • Manual PTT is only in the FM transceiver. Everywhere else the apps key the radio themselves. The build in this site has no global PTT.
  • FM and packet first. The boot gate is an acknowledgement, not a lock. OOK timing is limited by the PA settling time, about 1 ms per bit.

Try it on your DM-32UV

Back up the original firmware first. The flasher does that for you, then installs DM32Mayhem and leaves the codec and calibration alone.
